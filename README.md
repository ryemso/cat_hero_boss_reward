# Cat Hero 보스 보상 기록 · 정산

스크린샷에서 보상 카드를 찾고 U01~U33 템플릿에 연결한 뒤, 사용자가 보상/수량을 확인해 정산하는 프로그램입니다. **Windows 설치형**과 **GitHub Pages 웹형**을 제공합니다.

- 웹형: https://ryemso.github.io/cat_hero_boss_reward/
- 저장소: https://github.com/ryemso/cat_hero_boss_reward
- 배포/설치 ZIP: 저장소 **Actions → Test, package and deploy Pages → 성공한 실행 → Artifacts**

## 제작 이유

보스 보상 정보를 수집하고, 보스별·클리어 시간대별 보상 분포를 분석하기 위해 제작했습니다. 특정 보상이 유독 잘 나오지 않는다는 체감이 실제 기록에서도 나타나는지 확인하고자 시작했습니다.

처치 결과 스크린샷에서 보상과 수량을 인식하고, 사용자가 확인한 결과와 클리어 날짜·시간을 기록합니다. 수집한 데이터로 보상별 등장 빈도와 수량, 클리어 시간대에 따른 차이를 살펴보는 것이 목표입니다. 정산 기능은 이 기록 과정을 편하게 돕기 위한 기능입니다.

현재는 기록 수집과 관리자 조회·CSV 내보내기를 제공하며, 시간대별 분석은 수집 데이터로 진행할 예정입니다. 시간대가 보상에 영향을 준다고 미리 단정하지 않고 실제 기록을 통해 확인하려고 합니다.

## Windows 설치형

1. 저장소 `Code → Download ZIP` 또는 Actions의 `boss-settlement-install` ZIP을 내려받아 압축을 해제합니다. Actions artifact는 바깥 ZIP 안에 설치 ZIP이 한 번 더 들어 있습니다.
2. Python 3.11 **64bit**를 설치하고 `Add Python to PATH`를 선택합니다.
3. `install.bat`을 실행합니다. 설치가 끝나면 `run.bat`을 실행합니다.
4. 실행 콘솔은 앱을 사용하는 동안 열어 둡니다.

첫 설치에는 패키지 및 EasyOCR 모델 다운로드에 인터넷이 필요합니다. 숫자 인식에 실패하면 `OCR 실패: 수량 확인 필요`가 표시되므로 수량을 직접 확인하세요. `diagnose.bat`으로 Python/패키지 상태를 확인할 수 있습니다. 배치 파일은 ASCII + CRLF 형식입니다.

**기존 설치 업데이트:** 앱을 종료하고 `data/settlement.db`와 `data/templates/`를 먼저 복사해 백업합니다. 새 코드/스타터 템플릿을 덮어쓰되 이 DB와 사용자 템플릿 폴더를 유지합니다. 재실행 시 기존 DB에 진단 필드를 추가하고 예전 절대경로를 복구합니다. 새 ZIP에는 사용자 DB가 포함되지 않습니다.

Linux/macOS:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

## GitHub Pages 웹형

설치 없이 최신 브라우저에서 사용합니다. OpenCV.js 카드 검출/아이콘 매칭, Tesseract.js 숫자 OCR, 브라우저 데이터 저장을 사용합니다. 이미지 처리와 정산 데이터 저장은 현재 기기에서 이루어집니다. 개인 장부는 **다른 사용자/기기와 자동 동기화되지 않습니다**. 수집 계정 로그인 후 이미지 정산을 등록하면 보상 기록과 원본·마킹 이미지가 Supabase 관리자 수집함으로 자동 전송됩니다. `설정 · 백업`에서 JSON을 내려받아 다른 브라우저에 복원하세요. 브라우저 데이터를 지우기 전에도 백업하세요. 설치형 DB와 웹형 데이터는 별개입니다.

최초 배포는 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택한 뒤, Actions의 워크플로를 다시 실행합니다. 이후 `main` 변경마다 자동 테스트 → 빌드 → Pages 배포를 수행합니다. GitHub의 기본 워크플로 토큰으로 Pages를 최초 활성화하는 관리자 작업을 대신할 수 없으므로 이 최초 설정이 필요합니다. PR에서는 테스트/패키징만 수행합니다.

OCR 엔진, WASM, 영어 숫자 인식 모델 및 U01~U33 템플릿을 빌드 산출물에 포함합니다. 외부 OCR 서버로 이미지를 전송하지 않습니다. 초기 엔진 다운로드에는 시간이 걸릴 수 있으며, 점수가 낮거나 OCR이 실패한 카드는 사용자가 수정해야 합니다. 인식점수는 아이콘 유사도이며 정답 확률이 아닙니다. 숫자 신뢰도 역시 엔진의 참고 점수입니다.

로컬 웹 개발 (Node.js 22 권장):

```bash
cd web
npm ci
npm run build  # Python 3 필요: 기본 매핑/엔진 자산 생성
npm run dev
```

정적 호스팅 대상은 `web/dist`입니다. 루트 경로나 `/cat_hero_boss_reward/` 같은 하위 경로 모두 상대경로 빌드를 지원합니다.

## 사용 순서

1. `보스전 등록`에서 날짜/시간, 보스, 활성 참여자를 선택합니다.
2. 처치 결과 스크린샷을 업로드합니다. 획득 가능 목록 이미지는 템플릿 확인용이며 실제 지급된 보상 기록으로 등록하지 마세요.
3. **보상명, 수량, OCR 수량, 인식점수, 후보ID, 수량신뢰도, 등급, 매칭/수량 상태**를 확인합니다.
4. 점수가 낮으면 보상명은 미지정이지만 후보ID/후보보상/점수는 남습니다. 템플릿이 전혀 읽히지 않으면 점수는 공란으로 표시하고 경로 오류를 안내합니다.
5. `DEFAULT_ONE` 보상은 1개로 입력하며 OCR 수량/신뢰도는 공란입니다. `AUTO/OCR`은 숫자를 읽고 실패하면 기본 1과 확인 안내를 표시합니다. 실제 숫자가 1이라는 뜻은 아닙니다.
6. 올바른 활성 보상과 수량으로 수정한 뒤 정산 등록합니다. 설치형에서는 `다시 인식` 버튼으로 마스터/기준 변경 후 결과를 새로 가져올 수 있습니다. 웹형은 같은 이미지를 다시 선택하면 재인식합니다.
7. 정산 장부/전체 정산에서 결과를 확인하고 Excel을 내려받습니다.

## 참여자와 보상 관리

- 참여자: 추가, 이름 수정, 비활성화/재활성화, 삭제. 정산 기록에 참여한 사람은 삭제 대신 비활성화합니다. 기존 기록과 분배 인원수를 보존합니다. 기록이 없는 사람은 삭제할 수 있습니다.
- 보상: 이름, 등급(설치형), 수량 방식, 분배 방식, 1단위 값어치, 활성 여부 수정. 변경값은 재실행 후에도 유지합니다. U01~U33의 정산 컬럼과 후보 연결은 고정합니다.
- 비활성 보상: 이미지 후보로는 인식하며 신규 정산 등록 시 활성 보상으로 교체해야 합니다. 과거 기록은 유지합니다.
- 단가/분배 방식/환산 설정을 수정하면 과거 기록도 현재 설정으로 다시 계산합니다. 기간별 단가 스냅샷 기능은 없습니다.
- 설치형 `보상 마스터`에서 사용자 카드 템플릿을 등록할 수 있습니다. 웹형은 제공 U01~U33 후보를 사용합니다.

## 고정 매핑 / 엑셀 정산 구조

유일한 기본 매핑 원본은 `data/starter_mapping.csv`입니다. 웹형의 seed.json도 이 CSV에서 빌드합니다.

| 후보 | 보상 | 정산 컬럼 | 1단위 보라가치 |
|---|---|---|---:|
| U01 | 빨레 | 빨레 | 0 |
| U02, U18 | 보라레시피 | 보라레시피 | 3000 |
| U03, U19 | 파랑레시피 | 파랑레시피 | 130 |
| U04 | 초록레시피 | 초록레시피 | 10 |
| U05~U08, U24 | 파템 | 파템 | 4300 |
| U09~U10, U25~U27 | 초템 | 초템 | 650 |
| U11, U28~U31 | 흰템 | 흰템 | 100 |
| U12, U14, U32 | 룬 소환 | 룬 소환 | 0 |
| U13, U33 | 전설픽업 | 전설픽업 | 0 |
| U15~U16 | 동료소환 | 동료소환 | 0 |
| U17 | 랜덤 룬 | 랜덤 룬 | 0 |
| U20~U23 | 보 | 보 | 0 |

`픽뽑+픽업 → 전설픽업`, `룬 → 룬 소환`, `동 → 동료소환`, `룬뽑 → 랜덤 룬`. 빨레/보도 정산 수량과 합산 가치에 포함합니다. 초기 값어치는 0이므로 보상 마스터에서 단가를 설정하세요.

- EQUAL: 보상 수량 / 실제 참여 인원
- PER_PERSON: 입력 수량을 참여자마다 지급
- 보라가치: 개인 수량 × 1단위 값어치
- 현금: 보라가치 × 보라가치 100당 현금 / 100 (기본 500)
- 수수료 제외: 현금 × (1 − 수수료율) (기본 10%)
- 개인별 엑셀 컬럼 순서: 파템, 초템, 흰템, 전설픽업, 동료소환, 룬 소환, 랜덤 룬, 보라레시피, 파랑레시피, 초록레시피, 빨레, 보.

이 버전은 제공 ZIP의 정산 코드/CSV를 기준으로 구조와 단가를 유지했습니다. 별도 원본 Excel 파일은 이번 입력에 없으므로 Excel 파일 자체를 다시 대조한 결과는 아닙니다. 소환권/랜덤 룬의 초기 가치 0은 원본 프로그램 그대로이며 임의로 가격을 추가하지 않았습니다.

## 수정 내용과 검증

- 템플릿 경로를 프로젝트 기준으로 해석하고, 이전 Windows/다른 폴더의 절대경로를 복구합니다.
- 한글 Windows 경로에서 PNG 읽기/쓰기 실패를 피하도록 바이트 디코딩/인코딩을 사용합니다.
- 복수 U 후보가 하나의 보상 마스터에 연결되는 경우 각 후보의 이미지 경로를 정확히 읽습니다.
- 시작할 때 사용자가 수정한 이름/단가/활성 상태를 덮어쓰지 않습니다. 기본 참여자 삭제 후 재생성도 막습니다.
- 후보ID/수량신뢰도/등급을 DB와 원장에 보관합니다.
- 제공된 게임 이미지 7개를 회귀 검증에 포함했습니다. 기본 템플릿은 이 이미지들에서 만들어졌으므로 테스트는 연결/표시 오류 방지를 확인하며, 새로운 이미지 전체에 대한 정확도를 보장하지 않습니다.

```bash
python -m unittest discover -s tests -v
cd web
npm run build
npm test
npx playwright install chromium
npx playwright test
```

Python 테스트는 카드/매핑/UI/데이터 보존/분배/Excel을 검증합니다. 숫자 OCR 부분은 주입된 결과로 UI 연결을 검증하므로 EasyOCR 모델의 실제 인식 정확도 테스트는 아닙니다. 웹 브라우저 테스트는 제공 숫자 카드에서 800/150/150/120/120/5를 실제 OCR로 확인하며 참여자/보상 관리와 재실행 후 저장도 검증합니다.
